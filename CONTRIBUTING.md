# Contributing

Bug reports, questions and patches are all welcome. This is a small IP block, so the
process is short.

## Before you start

Everything the repository needs is open source and installable from a package manager:

| tool | version used here | what it does |
|---|---|---|
| Icarus Verilog | 12.0 | simulates the testbenches |
| Verilator | 5.020 | lints the RTL, `-Wall`, no warnings allowed |
| Yosys | 0.33 | synthesis, and the model for the formal proof |
| Python | 3.12 | test runner, reference renderer, report and image generation |

Those four are enough for `make lint`, `make test`, `make formal` and `make images`, which
is what continuous integration runs. The silicon flow additionally needs the
[IHP Open PDK SG13G2](https://github.com/IHP-GmbH/IHP-Open-PDK), OpenROAD with OpenSTA and
LibreLane; those targets are local because a plain GitHub runner has none of them.

```
make venv          # once, creates .venv and installs the Python dependencies
make lint          # Verilator -Wall over the RTL
make lint-config   # the same, with a second parameter set
make test          # every testbench, in parallel
make formal        # prove the sync generator properties
```

## What a change has to satisfy

1. **`make lint` and `make lint-config` are clean.** Zero Verilator warnings, both
   parameter sets. A warning is a failure, not a note.
2. **`make test` passes in full.** Fourteen cases. If a change alters what the display
   path produces, `scripts/model.py` has to be updated to match and the frame comparisons
   have to pass against the new model, not around it.
3. **New behaviour comes with a test.** The suite compares pixels against an independent
   renderer, so the useful pattern is: describe the scene in `scripts/scenes.py`, teach
   `scripts/model.py` the rule, and let the frame comparison do the checking. A test that
   reads internal signals to confirm what the RTL already does is worth much less.
4. **The RTL stays inside the SystemVerilog subset all three tools read.** Icarus Verilog,
   Verilator and Yosys. That means no `unique case` priorities, no package functions in
   synthesised paths, no interfaces, and elaboration time checks behind
   `` `ifndef SYNTHESIS ``. If Yosys cannot read it, the area and timing numbers stop
   existing.
5. **Documented numbers are measured.** `docs/pdk_area_report.txt`,
   `docs/sta_report.txt`, `docs/pnr_report.txt` and `docs/formal_report.txt` are all
   generated by a script in `scripts/` and committed. If a change moves the area or the
   timing, re-run the relevant target and commit the new report rather than editing the
   number in the README by hand.

## Style

- Two space indent, `snake_case` for signals, `PascalCase` for parameters and localparams.
- Port suffixes: `_i` input, `_o` output, `_ni` active low input. Flip flop outputs carry
  a `_q` suffix, their next state `_d`.
- `always_ff` for state, `always_comb` for combinational logic, `assign` for one liners.
  No `always @(*)`.
- Comments explain why, not what. The repository leans on this heavily: most modules open
  with a paragraph on the decision the module embodies. A patch that adds a mechanism
  should say what it costs and what the alternative was.
- Lines wrap at 100 columns, in the RTL, the testbenches and the Python.

## Commits

Conventional Commit prefixes, imperative mood, describing the change:

```
feat: add a 1280x1024 video mode
fix: hold the fetch request while the elastic buffer is one slot from full
docs: state the post route die area next to the synthesis cell area
test: cover the cursor at a zero blink divider
```

## Adapting rather than contributing

If what you want is a different grid size, a different DAC width, another video mode or
your own font, that is configuration rather than a change to this repository.
[`docs/ADAPTING.md`](docs/ADAPTING.md) walks through each of those.
